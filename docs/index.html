The shift

From a primitive to a product.

The primitive is done and running: pay-per-call settlement on-chain, gating real APIs. Speech and cost-routed LLM calls were the proof. The same rail, pointed at a frontier model, becomes something people actually want: metered access to Claude.

What we built

Pay-per-call, two live APIs

An agent signs an x402 authorization, the facilitator settles a CEP-18 transfer on Casper, and the rail returns the result. Speech priced per character, LLM calls per token and routed to the cheapest capable model. Real money, real APIs, a hard spend cap.

Roadmap

Four phases to agent-native Claude access.

Each phase ships something usable. We don't wait for the smart-contract escrow to put Claude behind the rail, we harden the guarantees as we scale.

01

The primitive

Shipped

Prove that an agent can pay for a real API, per call, on-chain, with a cap it cannot exceed.

  • x402 paywall (HTTP 402 + price) in front of live APIs
  • Own CEP-18 token on Casper testnet; facilitator verifies signatures and settles transfers, pays gas
  • Per-call settlement: one signed authorization, one on-chain transfer, a real result back
  • Usage-based pricing: speech per character, LLM calls per token not a flat toll
  • Cost-aware routing: the rail picks the cheapest capable model and prices the call to it
  • Bounded ceilings with credit back: reserved versus metered actual, reported per call
  • Live dashboard, house-funded demo, and a global on-chain settlement feed
02

Claude, metered

Next up

Point the rail at Claude. Pay-per-message chat, streamed back, priced by tokens.

  • New /v1/chat endpoint gating the Claude Messages API Anthropic
  • Token-accurate pricing: cost scales with input and output tokens, quoted in the 402
  • Streaming responses (SSE) with pre-authorization, settled on completion
  • "Chat with Claude, pay per message" web UI, where the demo becomes the product
  • Model choice: Opus, Sonnet, Haiku, each with its own per-token price
03

Developer platform

Planned

Let anyone build on the rail: keys, balances, metering, a drop-in SDK.

  • API keys tied to on-chain funded balances
  • Real-time usage metering: spend, remaining balance, per-call history
  • Per-key spend caps and rate limits set by the developer
  • Drop-in fetch wrapper SDK, so any app pays automatically on 402
  • Provider-agnostic gateway: many APIs behind one rail and one balance
04

Hard guarantees and scale

Vision

Make the spend cap a contract-enforced guarantee, then go wide.

  • Odra budget-escrow contract: cumulative ceiling and per-merchant sub-limits the agent physically cannot exceed
  • Mainnet launch
  • Fiat on-ramp: top up a balance with a card, for users who never touch crypto
  • Multi-provider marketplace: Claude alongside other premium APIs, one rail
  • Agent-to-agent payments: agents settling each other's Tabs autonomously
